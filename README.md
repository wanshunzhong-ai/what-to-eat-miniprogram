# 今天吃什么 🍽️

一个解决「一日三餐吃什么」的**微信小程序**：**定位识别城市 → 选人数 → 一键推荐**。
两条路可选：**🍳 自己做**（推荐一桌菜 + 做法）或 **🛵 点外卖**（推荐附近的店）。

> 纯微信小程序项目（WXML / WXSS / JS），并已接入**微信云开发（CloudBase）**：
> 推荐计算优先在云函数里执行，云端不可用时自动降级为本地同款逻辑，离线也能用。

## ✨ 功能

### 🍳 自己做

- **自动定位**：调用 GPS 拿到经纬度，自动匹配最近的城市（内置 130+ 城市坐标，无需任何地图 Key）
- **按城市推荐**：识别城市后，优先推荐当地菜系（成都→川菜、广州→粤菜、西安→西北菜…）
- **按人数配菜（照风俗习惯来，人数 15 人内）**：选完人数后当场给出**冷热菜配比建议**（凉菜 / 荤 / 素 / 汤 / 主食各几道），食材用量同步按人数换算（如「嫩豆腐 450 g」）。人数 1~15 都可选，快捷选项 1~15 人，也可用「＋ / −」步进器微调
- **智能搭配**：一桌菜自动保证荤 / 素 / 汤 / 主食的搭配，不重复、不翻车；本地菜系优先，缺项才用家常菜兜底
- **口味偏好**：辣度（不吃辣 / 微辣 / 中辣 / 重辣）、是否清淡、希望的做菜时间
- **做菜时间是软偏好**：只是优先推荐快手菜，**不会把慢菜一刀切掉**；凑不齐时才逐步放宽
- **换一批**：不满意就一键换一批
- **菜品详情**：食材清单（按人数换算）、做法步骤、小贴士，可收藏

### 配比规则（中式用饭惯例，非硬性规定）

| 人数 | 凉菜 | 热菜 | 汤 | 主食 | 依据 |
|---|---|---|---|---|---|
| 1–2 人 | 0 | 2（荤素相当） | 0 | 1 | 人少不上凉菜，清爽不浪费 |
| 3–5 人 | 1–2 | 3–5（荤略多于素） | 1 | 1 | 「一人一热菜」的家常习惯 |
| 6–10 人 | 2–3 | 6–10（荤约为素的 1.5 倍） | 1 | 1 | 待客「N 菜一汤」 |
| 11–12 人 | 4（四冷盘封顶） | 11–12 | 2 | 2 | 宴席规格，双汤双主食 |
| 13–15 人 | 4 | 13–15（一人一热菜，封顶 15） | 2 | 2 | 十五人大席，一桌摆开 |

> 冷盘最多 4 道（传统「四冷盘」即上限）；热菜按「一人一道」最高 15 道（人数上限 15，再多就该分两桌）。早餐不讲冷热配比，以**主食 + 小吃**为主，人多再加轻食 / 汤。

### 🛵 点外卖

- **附近的真实店铺**：定位后列出你周围的餐馆，显示**店名 / 距离 / 地址 / 电话**
- **品类筛选**：全部 / 早餐 / 快餐简餐 / 面食米线 / 盖饭套餐 / 小吃 / 家常炒菜 / 火锅 / 烧烤烤肉 / 甜品饮品 / 西餐 / 日料 / 韩餐
- **按「人数 + 预算」排序**：一个人更适合单份快餐，人多更推火锅烤肉；预算档位（20 元内 / 20-50 / 50-100 / 100+）只改排序，不重新请求
- **一键导航 / 打电话 / 复制地址**：导航打不开时自动退化为复制地址
- **店铺收藏**：喜欢的店收藏起来，下次直接看
- **兜底**：没配置地图 Key 或网络失败时，不会白屏——给出明确提示与当地人气美食指引

### 通用

- **本地人气**：推荐该城市/菜系值得一吃的特色小吃
- **历史 & 收藏**：记录每次「自己做」和「点外卖」，带类型标签，可一键复现

## ☁️ 云开发（CloudBase）接入

### 它是怎么工作的

```
首页点「帮我决定」
      │
      ▼
utils/engine.js ──► 云函数 recommend（云端跑推荐逻辑）
      │                    │ 成功
      │                    ▼
      │              返回一桌菜结果
      │
      └─ 未启用 / 初始化失败 / 调用失败 ──► 本地 utils/recommender.js（结果一致）
```

- 小程序启动时在 `app.js` 里 `wx.cloud.init({ env, traceUser: true })` 初始化一次。
- 推荐统一走 `utils/engine.js`：**云端优先，本地兜底**，任何一步失败都不会影响使用。
- 云端与本地复用**同一套** `recommender / cities / dishes / foodData`，结果一致。

### 运行环境兼容（`utils/wxapi.js`）

不同运行环境实现的 `wx` 接口并不一致——真机、开发者工具、**预览沙箱**之间都有差异。
例如预览环境没有实现 `wx.getLocation`，若直接调用会抛 `wx.getLocation is not a function`，
`onShow` 等生命周期会被这个异常打断，页面看起来就像"没跑起来"。

因此 `app.js` 启动时会调用 `wxapi.install()`，做两件事：

- **缺失接口兜底**：对 `showToast / showModal / navigateTo / pageScrollTo` 等非关键接口，
  缺失时补一个安全实现（真机上这些接口都存在，不会被替换，行为完全不变）；
  同步存储缺失时用内存实现兜底，预览环境里收藏/历史依然可用。
- **定位走安全层**：定位统一调用 `wxapi.getLocation()`（Promise 版，**绝不抛异常**），
  依次尝试 `getLocation` → `getFuzzyLocation`，都没有时返回"环境不支持"，
  页面改为提示手动选城市（预览环境会默认取一个人气城市并明确提示，保证功能可用）。

> 结论：**不要再在页面里裸调 `wx.getLocation`**，请统一用 `wxapi.getLocation()`。

### 定位精度策略（`wxapi.getLocation` + `cities.findNearest`）

识别城市准不准，取决于「设备给的坐标准不准」和「匹配算法准不准」两段，这里两段都做了处理：

**第一段 · 拿到尽量准的坐标**（`wxapi.getLocation`）

| 做法 | 说明 |
|---|---|
| 开启高精度 | `isHighAccuracy: true` + `highAccuracyExpireTime: 8000`。**不要关掉**——关掉后微信只给基站/网络级位置，偏差常见几百米到几公里 |
| 多次采样取最优 | 精度 > 50m 时自动再采一次，取 `accuracy` 最小的一次（最多 2 次） |
| 短时快照复用 | 2 分钟内的定位结果直接复用，避免刚定位完又被降级成粗略值 |
| 精度可见 | 结果带 `accuracy`（米），首页会显示「精度约 ±35 米」，模糊定位会显示「±2 公里（较粗略）」 |
| 强制重新定位 | 「🎯 重新定位」按钮传 `fresh: true`，跳过快照 |

**第二段 · 匹配置信度**（`utils/cities.js`）

- **131 座城市**（地级市为主），覆盖全国；`findCandidates()` 按距离升序返回候选。
- **直辖市多锚点**：北京/上海/天津/重庆辖区跨度数百公里，单点中心会把远郊区县判给隔壁城市
  （如「重庆万州」曾匹配到南充）。这些城市带 `anchors` 数组，匹配时取「市中心 + 各锚点」的最近距离。
- **跨界不瞎猜**：最近的两座城市距离相差 < 25km **且菜系不同**时，标记 `ambiguous`，
  首页弹候选让用户点一下确认（同菜系的相邻城市不打扰用户）。
- **附近无收录城市**：最近城市 > 150km 时标记 `lowConfidence`，首页明说「已按最近的 X 推荐，相距约 N 公里」。
- **「离你最近」列表**：城市选择页会按定位距离列出最近 6 座城市（带公里数），识别不准可直接点选更正。

- 注意：**微信测试号不支持云开发**；腾讯云侧创建的环境默认面向 Web，要在小程序端使用需按上面步骤导入。

## 🛵 接入附近店铺（腾讯位置服务）

「点外卖」要列出**你附近的真实店铺**，这只能靠地图服务商的 POI 接口。项目已把这条链路接好，
**只差一个地图 Key**。可先不配——不配时外卖页会给出明确提示与当地人气美食指引，不会白屏。

### 架构

```
pages/takeout ──► utils/engine.js ──► 云函数 nearby ──► 腾讯位置服务 周边搜索
    │                                                       (Key 存环境变量)
    └─ 拿不到位置/失败 ──► 明确的空态提示（未配置 / 无结果 / 请求失败 三种）
```

**Key 为什么放在云函数里？**

1. Key 是敏感凭证，放云函数**环境变量**里不会下发到小程序前端；
2. 云函数出网不受小程序「request 合法域名」白名单限制，**省去后台配置**；
3. 腾讯侧的错误码可以在服务端统一翻译成人话再给前端（如「IP 未授权」「Key 未开通 WebServiceAPI」）。

### 申请并使用 Key（约 3 分钟）

1. 打开 [腾讯位置服务控制台](https://lbs.qq.com/dev/console/key/manage)（用微信/QQ 登录），
   进入「**应用管理 → 我的应用**」→ **创建应用** → 在应用下 **添加 Key**。
2. 添加 Key 时**务必勾选「WebServiceAPI」**（周边搜索属于 WebService 能力），
   IP 限制可先留空（不限 IP）。
3. 复制这串 Key，在微信开发者工具的云开发控制台里配置环境变量：

   **云开发控制台 → 云函数 → `nearby` → 配置 → 环境变量**，新增：

   | 变量名 | 值 |
   |---|---|
   | `TENCENT_LBS_KEY` | 你刚申请的 Key |

4. 确认 `cloudfunctions/nearby` 已上传：在开发者工具文件树里右键该目录 → **「上传并部署：云端安装依赖」**。
5. 回首页切到「🛵 点外卖」→ 点「看看附近有什么」，即可看到真实的附近店铺。

> 想本地调试不部署云函数也行：把 `config.js` 的 `NEARBY_FN` 指向你本地起的一个等价代理即可，
> 但**不建议把 Key 直接写进小程序代码**——那样前端能反编译出来。

### 常见报错对照

| 现象（外卖页提示） | 原因 | 处理 |
|---|---|---|
| 「还没配置腾讯位置服务 Key」 | 环境变量 `TENCENT_LBS_KEY` 没配或为空 | 按上面第 3 步配置 |
| 「该 Key 未开通 WebService API 权限」 | 申请 Key 时没勾 WebServiceAPI | 回控制台修改 Key 的勾选项 |
| 「Key 的调用来源未获授权」 | Key 限制了来源 | 取消来源限制，或把云函数出口 IP 加白名单 |
| 「每日调用量已达上限」 | 免费额度用尽 | 控制台查看配额，或次日再试 |

> 半径默认 3 公里（`config.js` 的 `NEARBY_RADIUS`），搜索时带「结果不足自动向外扩展」标记，所以不必设太大。
> 地图接口**不返回价格**，页面上的「参考人均」是按品类给出的经验区间，属于估算，已以「参考人均」字样标注以免误导。

## 🛠️ 如何扩充

- **加菜**：在 `utils/dishes.js` 里按现有格式追加一条即可（id 不要重复）
- **加城市**：在 `utils/cities.js` 的 `CITIES` 里加一行（名称、省份、经纬度、菜系）
- **加本地美食**：在 `utils/foodData.js` 里补充
- **加外卖品类**：在 `utils/takeout.js` 的 `CATEGORIES` 里加一项，并在 `CAT_RULES` 里补上识别关键词

改完数据后，把 `utils/` 下对应的 `cities.js / dishes.js / foodData.js / recommender.js`
同步复制到 `cloudfunctions/recommend/`，再在开发者工具里重新上传该云函数。
